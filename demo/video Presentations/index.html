Way of working 1 · 2:18

SRS-first onboarding

Sign up, upload the requirements document — the project is created for you and filled in by Claude.

  1. Upload a .pdf, .txt or .md SRS (up to 10 MB); the Project Key defaults to the file name.
  2. Review what Claude extracted: requirements, use cases, components, API endpoints.
  3. Open the pre-filled wizard: add the start date, assign real people to the default team, add the agenda / process / decisions.
  4. Generate the WBS — resource loading is checked first.

Way of working 5 · 0:52

Managing projects

Create a project without an SRS, switch between projects, and tidy up when work is done.

  • Create manually — the same wizard with a blank draft
  • Archive hides a project but keeps its data; Restore it from the start screen
  • Delete is permanent, and offers Archive instead
  • Only the project owner can archive or delete it

Try it

Run it yourself

With Docker

cd backend  && npm install && cd ..
cd frontend && npm install && cd ..
# .env (repo root): JWT_SECRET, ANTHROPIC_API_KEY
docker compose up -d --build

Then open http://localhost:8081 and sign up.

Without installing anything

The interactive demo runs in any browser — no backend, no account. Switch to Explore to click through every chapter yourself.

Full documentation — setup, environment variables, API and troubleshooting — is in the project README.md.
